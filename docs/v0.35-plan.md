# OpenLayer v0.35.0 — Qwen-Image 2.1: review, audit and release plan

Written 2026-09-23 against `main` at `8060a7b` (v0.30.0) and a live ComfyUI **0.37.0** on
`127.0.0.1:8188` (RTX 4070 Ti 12 GB, 32 GB RAM, torch 2.13.0+cu130). Every number below was
measured on that machine unless it is marked as a source claim.

> **Decision needed before any code: the licence.** Qwen-Image 2.1 is released under the
> **Qwen RESEARCH LICENSE AGREEMENT**, which defines non-commercial as *"for research or
> evaluation purposes only"* and requires a separate licence for commercial use
> ([LICENSE](https://huggingface.co/Qwen/Qwen-Image-2.1/blob/main/LICENSE), read directly).
> Every other Qwen image model OpenLayer touches — Qwen-Image-Layered (Unflatten), 2512,
> Edit-2511 — is Apache-2.0. 2.1 is the first one that is not. This plan assumes 2.1 ships
> the way FLUX.1-dev and FLUX.2-dev already do: **opt-in presets behind a `licenseGate`,
> never a default, never marketed as a tool for client work.** If that is not acceptable,
> skip to §6.

## 1. What Qwen-Image 2.1 is (verified on this rig)

A single 2.1 model does text-to-image, instruction editing and multi-image composition. ComfyUI
supports it with **core nodes only**, which landed on 2026-09-20 (`6bfaacc6`,
"Qwen-image 2.1 support"):

| Node | What matters for OpenLayer |
|---|---|
| `UNETLoader` → `qwen_image_2.1_int8_convrot.safetensors` | 7.26 GB, fits 12 GB |
| `CLIPLoader` type `qwen_image` → `qwen3vl_8b_w4a8.safetensors` | 6.31 GB. The official template names `qwen3vl_8b_int8_convrot` (9.35 GB); w4a8 is a real file in the same repo and works |
| `VAELoader` → `qwen_image_2.1_vae_bf16.safetensors` | 0.68 GB. **4-channel (RGBA) VAE** |
| `TextEncodeQwenImage21` | prompt, negative, `resolution` (reference pixel budget, 0 = native), autogrow **`images.image_1` … `images.image_16`**, optional vae. Outputs positive, negative, and a LATENT sized from image_1 |
| `QwenImage21Cache` | experimental KV-cache placement/quantisation; not needed at 1 MP |
| `KSampler` | cfg **1** (negative prompt is inert at cfg 1), euler / simple, 25 steps |

All three files are **already on disk** (downloaded 2026-09-22). Total download for a new user:
**14.25 GB**. The official Comfy templates (`image_qwen_image_2_1_t2i`, `…_image_edit`,
`…_background_removal`) wrap the graph in a **subgraph**; OpenLayer's injection model needs flat
node ids, so the shipped graphs are rebuilt flat (they are 8–12 nodes).

| Test | Result | Time |
|---|---|---|
| Text to image, 1 MP, poster with two text lines | Both lines spelled exactly | 14–22 s |
| Text to image, **2048²** native, handwritten note | Correct handwriting, clean detail | 86 s |
| Same portrait at 12 vs 25 steps | 12 steps usable but saves only ~2 s — overhead dominates | 12 s vs 14 s |
| **Transparent generation** (RGBA prompt wrapper) | Real alpha: 69% fully clear, clean handle hole, soft contact shadow | 16 s |
| Instruction edit on a real photo (change sign text + rain relight) | Sign rewritten exactly, composition held | 23 s |
| 2 references (scene + **transparent** teapot layer) | Placed, lit; scale too large | 54 s |
| 3 references (scene + person + teapot) | Person's hair/sweater and the teapot carried in | 82 s |
| **Background removal** — template's isolated sample | Works (57% clear) | 22 s |
| **Background removal — real photo, person in a street** | **Fully transparent empty frame, 4/4 runs** (template settings, resolution 0, explicit prompt, and a second text encoder) | 22 s |

### 1.2 Behaviour that shapes the design

1. **Every output is RGBA — even "opaque" ones.** Opaque images come back with alpha 248–252 on
   ~10% of pixels. Imported raw, they would be faintly see-through layers. Opaque presets must
   end in `SplitImageWithAlpha` → `SaveImage` (verified: a true `mode=RGB` PNG).
2. **`LoadImage` drops alpha.** It returns RGB plus an inverted MASK. To feed a transparent
   Photoshop layer as a reference, route `LoadImage → JoinImageWithAlpha(image, mask)`. The
   encoder composites alpha over white for the vision tower and gives the VAE all four channels.
3. **Edits are geometrically aligned but not colour-preserving.** Phase correlation measured a
   0–1 px shift against the source, but "untouched" regions darken by 6–12 levels (MAD 17–24).
   A whole-image edit is fine as a new full-frame layer; a **local** edit must be imported
   through the selection layer mask, or the drift shows everywhere outside the edit.
4. **Output size follows image_1** at about `resolution`² pixels, rounded to multiples of 32 —
   a 3:2 source at 1024 comes back 1248×832. The existing import-and-scale path already handles
   a result that differs from the capture size.
5. **Multi-reference cost grows ~+28 s per reference** (1 → 23 s, 2 → 54 s, 3 → 82 s).
6. **Prompt tokens:** references are addressed as `<image1>`, `<image2>` … in the prompt.
   image_1 is the edit target / canvas. This is different from Klein's "the first image".
7. Upstream issue [ComfyUI#16447](https://github.com/comfy-org/ComfyUI/issues/16447) (open):
   the fixed shift only matches the model's dynamic schedule near 1024², so 2K may be slightly
   sub-optimal until it is fixed. 2K looked good here regardless.

### 1.3 Capability → OpenLayer fit

| 2.1 capability | Verdict | Where it goes |
|---|---|---|
| Text to image, exact typography, native 2K | **Ship** | Text to Image preset |
| **Transparent (RGBA) generation** | **Ship — the headline** | Text to Image "Transparent background" option |
| Instruction editing (text, relight, restyle) | **Ship** | Image to Image preset, beside `edit-flux2-klein` |
| Multi-reference composition (up to 16), RGBA refs | **Ship** | Multi-Reference preset, beside Klein |
| Local edit of a selection | Ship if the gate passes (task 6) | Image to Image with a selection → masked import |
| Background removal | **Do not ship** — fails on real photos | BiRefNet Remove Background stays |
| Prompt enhancer (`qwen3.5_9b_…_pe_t2i/_pe_i2i`) | **Defer** — 2 × 9.47 GB for a prompt rewrite | SuperPrompt stays |
| GGUF quants (`leejet/Qwen-Image-2.1-GGUF`) | **Defer** — needs `leejet/ComfyUI-GGUF`, not the registered `city96` pack | — |
| bf16 weights (13.25 GB diffusion) | **Defer** — no 12 GB story | — |
| Mask-conditioned inpaint | **Not offered by the model** — no mask input exists | — |

## 2. Architecture audit

**Health today:** typecheck passes (3.4 s), lint 0 problems (5.3 s), **1,053 tests in 104
files pass** (11.2 s). No import cycles across the 90 `src` files. `package-lock.json` is the
authoritative lockfile (CI runs `npm ci`); the pnpm files are ignored local leftovers.

### 2.1 Shape of the code

| Module | Role | Note |
|---|---|---|
| `src/ui/App.ts` (9,475 lines) | Everything the panel does | Lines 540–7160 are the `renderApp` closure — **6,621 lines, 167 inner functions, 61 mutable `let`s**. The 2,315 lines below it are 110 pure module-level functions and can move out with import rewiring only |
| `src/comfy/presetRegistry.ts` (4,662) | Single source of truth for 31 presets | Setup, footprint, health and dropdowns all derive from it — the design is sound; the file is simply long |
| `src/comfy/workflowBuilder.ts` (908) | Injects values into API graphs | Only two builders change graph shape: `applyReferenceChain` and `applyLoraSelection` |
| `src/photoshop/photoshopAdapter.ts` (3,319) | Capture, place, mask | Import passes the ComfyUI PNG through untouched and places it — **RGBA survives**; Unflatten already relies on this |
| `bridge/` | MCP server + WebSocket hub | Separate package, own lockfile |

Two surfaces do **not** derive from the registry: Live Painting builds its graphs in code, and
`hardwareAdvisor.ts` is hand-written text. The only layering inversion is `src/comfy` importing
`ui/appConstants` (two files) — harmless until `appConstants` ever imports from comfy.

### 2.3 Docs that no longer match the code (fix in task 8)

- `known-limitations.md` still calls Z-Image, Florence-2, `upscale-basic` and `flux1-dev-fp8`
  experimental (all stable), counts three Inpaint presets (four) and three Klein presets (five),
  and names `ae.safetensors` for Klein (it is `flux2-vae.safetensors`).
- README says every preset has an editable twin (8 do not), every tool is reachable over MCP
  (Live Painting is not), and results land aligned (Remove Background and Layer Maps do not).
- `roadmap.md` says every surface derives from the registry and lists the wrong experimental set.
- `SECURITY.md` describes network use as ComfyUI-only; the manifest also grants Hugging Face
  downloads and the bridge.

### 2.4 What this means for adding Qwen-Image 2.1

Adding a preset to an existing tool touches: the API graph, the source graph, the `WorkflowPreset`
union in `types.ts`, `presetRegistry.ts`, the `WORKFLOW_TEMPLATES` import in `workflowBuilder.ts`,
and the frozen lists in `presetRegistry.test.ts:34-50` and `modelFolders.test.ts:223-228`.
Dropdowns, Setup, footprint and health follow automatically. No new loader class and no custom
node, so `modelFolders.ts` and `setupManifest.ts` need no new kinds. Traps found on the way:

- **`requiredInputs` must name `images`, never `images.image_1`** — setup validation checks names
  against `/object_info`, which declares only the autogrow parent.
- **Use core `SaveImage`**, not the template's `SaveImageAdvanced` — `getSaveImageNodeId` only
  finds the former (`App.ts:7410`).
- **LoRA compatibility lists "qwen" as a foreign token** (`loraCompatibility.ts:54`), so the
  presets must declare their own `familyTokens` or they will flag their own LoRAs.
- Multi-Reference UI text is Klein-specific in five places (`appMarkup.ts:1249, 1262, 2193`,
  `App.ts:5355, 5426`) plus the MCP tool description (`bridge/src/tools.mjs:303-312`).
- Text to Image already allows 2048² (`settings.ts:153-163`); no per-preset megapixel cap is needed.

### 2.5 Structural recommendations (not for v0.35)

1. **Move the 110 pure functions below `renderApp` into modules** — import rewiring only, a
   different risk class from touching the closure. Good Codex work.
2. **Give the closure's 61 `let`s a state object**, one tool at a time, before any per-tool split.
3. **Split `presetRegistry.ts` by family** (`presets/klein.ts`, `presets/qwen.ts`…) once 2.1 lands.
4. **Bring Live Painting and the hardware advisor under the registry**, so Setup can list what
   Live Painting needs.
5. **Bridge auth:** a per-session token the panel shows and the MCP server presents.

## 3. The v0.35.0 release plan

**Headline:** *"Generate transparent layers, edit with words, compose from many layers — Qwen-Image
2.1 in Photoshop."* Four capabilities, three presets, one new option, zero new tool screens.
Every 2.1 preset sits **beside** an existing Apache-licensed default and never replaces it.

**Requirements for users:** ComfyUI **0.37.0 or newer** (first release with the nodes,
2026-09-20), 14.25 GB of downloads, 12 GB VRAM measured working. No custom node packs.

Process as usual (`docs/release-checklist.md`): branch `release/v0.35.0`, one commit per task,
`npm run typecheck && npm test` after every task, and a real Photoshop gate after every task
that changes what the panel does. Tasks that touch `styles.css` or markup go to the gate
**alone**.

### Task 0 — Branch and version bump
Bump `package.json`, `bridge/package.json`, `src/manifest.json`, `APP_VERSION`; run
`versionConsistency.test.ts` and let it name the rest. No gate.

### Task 1 — Three flat graphs, validated live
- `src/workflows/api/txt2img-qwen-image-21.json` — loaders → `TextEncodeQwenImage21` →
  `EmptyLatentImage` → `KSampler` (cfg 1, euler/simple, 25) → `VAEDecode` →
  **`SplitImageWithAlpha`** → `SaveImage`.
- `src/workflows/api/edit-qwen-image-21.json` — as above, plus `LoadImage` →
  `JoinImageWithAlpha` → `images.image_1`, latent taken from the encoder's third output.
- `src/workflows/api/multi-reference-qwen-image-21.json` — image_1 plus one template slot.
- Matching GUI sources in `src/workflows/source/`, produced by loading each API graph into the
  ComfyUI editor from the Browser pane (`app.loadApiJson` → `app.graph.serialize()`), no hand
  work. **Loading replaces whatever is on your ComfyUI canvas, so this step waits for your OK.**
- Each graph is submitted once to `/prompt` and left to finish (no interrupts, no queue clears).
All three graphs already ran successfully in the spike; this task makes them repo files.

### Task 2 — Registry: licence gate, model stack, Text to Image + Edit presets
- `QWEN_IMAGE_21_LICENSE` gate beside `FLUX1_DEV_LICENSE`, worded: *"Qwen restricts these
  weights to research and evaluation use; commercial use needs a separate licence from Qwen.
  Read the licence before downloading them or publishing work made with them."*
- `QWEN_IMAGE_21_STACK`: the three files with exact byte sizes (7,256,783,064 /
  6,312,105,364 / 675,509,688) from `Comfy-Org/Qwen-Image-2.1`.
- Presets `txt2img-qwen-image-21` and `edit-qwen-image-21` (mode `img2img`), status `beta`,
  recommended steps 25, cfg locked at 1, negative prompt hidden (it is inert at cfg 1).
- `requiredNodes` lists `TextEncodeQwenImage21` (with `requiredInputs` naming `images`, not
  `images.image_1`), so an older ComfyUI gets the existing missing-node message — check that it
  tells the user to update to 0.37.0.
- Declare `familyTokens` so the LoRA check does not treat "qwen" as foreign; core `SaveImage`.
- Correct the gated-model Setup note (`setupTabModel.ts:211-214`): the files are public on
  Comfy-Org's mirror; the gate is about *use*, not sign-in.
- Update the frozen inventories the suite names (see §2.4).
**Gate — what to check in Photoshop:** Setup tab shows the licence click-through; Text to Image
with the 2.1 preset renders a poster with readable text; Edit changes a sign on a photo layer;
both results are **fully opaque** layers (lock transparency has no effect / Load Selection from
the layer's transparency selects the whole canvas).

### Task 3 — Multi-Reference: a second wiring strategy
`referenceChain` becomes a discriminated union. Klein keeps `kind: "reference-latent"` unchanged;
2.1 gets `kind: "encoder-image-slots"` — for reference *k* the builder clones `LoadImage` +
`JoinImageWithAlpha` and sets `images.image_k` on the encoder node. New preset
`multi-reference-qwen-image-21`, `maximumReferences: 6` (measured to 3, ~+28 s per reference,
so 6 ≈ 3 minutes — state it on screen). With this preset the prompt hint uses `<image1>`,
`<image2>` … and the reference list shows the same numbers. Transparent reference layers keep
their alpha all the way into the encoder. Three audit items belong here because this task
touches the same code:
- switching the Multi-Reference preset must apply its recommended steps/CFG
  (`App.ts:2053-2056`), or 2.1 runs at Klein's 4 steps;
- the Klein-only wording in five UI places and the MCP tool description becomes preset-driven;
- register the missing Preview-panel import handler for Multi-Reference.
**Gate:** three layers — a background photo, a person, a transparent product layer — composed
in one run; the product's cut-out edge is respected.

### Task 4 — Transparent layers (the headline, UI change — gated alone)
- Preset capability `transparentOutput` on `txt2img-qwen-image-21`.
- Text to Image shows a **"Transparent background"** checkbox only when the selected preset
  has that capability.
- When it is ticked, the builder wraps the prompt at build time — the prompt field and history
  keep exactly what the artist typed — and rewires `SaveImage` to the RGBA `VAEDecode` output,
  bypassing `SplitImageWithAlpha`.
- The result imports as a transparent layer (see §2 on the import path).
**Gate:** "a red ceramic teapot" with the box ticked lands as a cut-out layer on a checkerboard;
unticked, the same prompt is opaque.

### Task 5 — Agent Bridge parity
`text_to_image` gains `transparent_background`; the three presets are selectable through the
existing preset parameters; `tests/e2e/agentBridgeEndToEnd.test.ts` covers the new flag. Keeps
the v0.30 promise that every tool is reachable from the bridge.

### Task 6 — Edit a selection, not the whole layer (spike first, cut if it fails)
With an active selection, `edit-qwen-image-21` captures the selection plus context (the
existing crop logic), edits, and imports through
`importImageAlignedToSelectionWithLayerMask`. Because unedited pixels drift 6–12 levels, the
spike measures seam visibility at a feathered mask edge on three real photos first. **If the
seam shows, v0.35 ships whole-layer edit only and says so in known limitations.**

### Task 7 — Audit fixes (one commit each)
- **7a** Remove Background and Layer Maps import at `captureBounds`, like Image to Image.
  *Gate:* cut out an off-centre layer; the cutout lands exactly over it.
- **7b** Register the Preview-panel import handler for Unflatten.
- **7c** Read every textarea as `field.value ?? ""` (11 sites + `appBindings.ts:136`) —
  mechanical, a good Codex task; *gate:* Generate with an empty prompt shows its message.
- **7d** Delete the "Spike: Model Download" button and `spikeModelDownload.ts` — markup
  change, so it goes to the gate alone.
Deferred to v0.36 with the §2.5 work: bridge auth, dead code and unused CSS, e2e in CI.

### Task 8 — Docs and release
CHANGELOG, README model table with a **licence column that says "research only"**, landing
page, `known-limitations.md` (why 2.1 background removal was not adopted, the licence, 2K
schedule issue, multi-reference timing), the §2.3 corrections, `release-checklist.md` smoke
steps, setup pack,
package, checksums, tag, refresh `latest`.

### Out of scope for v0.35 (and why)
| Item | Reason |
|---|---|
| 2.1 background removal | Empty frame on a real photo, 4/4 runs |
| 2.1 prompt enhancers | 2 × 9.47 GB to rewrite a prompt; SuperPrompt already does this |
| GGUF / bf16 variants | Different custom-node repo / no 12 GB story |
| Making any 2.1 preset a default | Research-only licence |
| Replacing Unflatten's Qwen-Image-Layered | Different model, Apache-2.0, still the best at its job |

## 4. Decisions (answered by Mehran, 2026-09-23)

1. **Licence — ship 2.1 as gated, opt-in presets.** Same treatment as FLUX dev.
2. **Task 6 — try it in v0.35**, and cut it if a visible seam appears.
3. **ComfyUI — free to use** for building and validating the graphs.

## 5. Not verified yet

- Whether 2.1 carries **a real person's face** through multi-reference — the 3-reference test
  used a generated face, and Klein's own preset text says faces are not carried. A gate with
  one of your own photos would settle it; it would be a genuine differentiator.
- 2K timings at non-square sizes, and any gain from `QwenImage21Cache` on 4+ references.
- Speed on a machine without `triton-windows` (int8 may fall back to a slower path — source
  claim, [comfy-kitchen#78](https://github.com/Comfy-Org/comfy-kitchen/issues/78)).

## 6. If the licence is a no

v0.35 still carries tasks 0, 7 and 8 plus the architecture work in §2, and the 2.1 graphs stay
in `docs/` as measured, unshipped evidence — ready for the day Qwen releases 2.1 (or a
successor) under Apache-2.0, as it did for every earlier Qwen image model.
