# OpenLayer v0.37.0 — Reference layers inside an edit

Mehran, 2026-09-24: "a must-have". Edit Image (Qwen-Image 2.1) gains a list of **reference layers**,
so an instruction can bring something in from another layer: *"put the jacket from `<image2>` on
her"*, *"replace the cart with the teapot from `<image2>`"*.

## Proven before planning (2026-09-24, live, core nodes only)

The v0.36 edit graph, a **selection** capture, plus one reference wired to `images.image_2` of the
same `TextEncodeQwenImage21`: "Replace the wooden cart in `<image1>` with the red teapot from
`<image2>`" put a transparent teapot layer into the selected area, lit to match, with no visible
seam, in 66 s on the 12 GB rig. The edit target stays `<image1>`; references are 2..n.

## Design

- **Reuse, don't rebuild.** The encoder-slot wiring (`encoder-image-slots`) and the reference-list
  UI both exist from Multi-Reference (v0.35). The edit preset gains a `referenceChain` of that kind
  whose slot 1 is the edit target, so references start at slot 2.
- **Screen:** under the source card in Edit Image, a compact "Reference layers" list with Add Layer /
  Add Canvas, shown only for presets that accept references (Qwen-Image 2.1). The hint says to name
  them `<image2>`, `<image3>`… in list order.
- **Works with every source:** a captured layer, the canvas, or a selection (colour match and
  corner anchors unchanged).
- **Ceiling 4 references** at first (+~30 s each measured in v0.35), raised if tests allow.
- **Agent Bridge:** `edit_image` cannot capture layers, like `multi_reference`; it uses the list the
  panel holds.
